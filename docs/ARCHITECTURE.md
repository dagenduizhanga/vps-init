# vps-init 架构与约定

## 目标

用 Bash 实现轻量、模块化的 VPS 初始化工具。交互菜单、命令行和单独运行的模块共用一套公共函数，不引入额外的运行时依赖。

## 结构

| 路径 | 职责 |
| --- | --- |
| `install.sh` | 远程启动器：按 `VPS_INIT_REF`（默认 `main`）下载源码到临时目录运行，结束后清理；不做任何系统修改 |
| `vps-init.sh` | 命令入口、交互菜单、状态面板 |
| `lib/common.sh` | 版本号、界面输出（颜色、对齐、步骤）、交互（`ask` / `confirm`）、`run_task`、系统检测 |
| `modules/*.sh` | 各功能模块，可单独运行；统一提供 `status`（详细状态）、`summary`（菜单面板的一行摘要）、`--help` |
| `tests/` | `smoke.sh`（无需 root）、`ssh.sh`（真实 sshd）、`interactive.py`（pexpect 交互）、`stubs/`（测试替身） |
| `ssh-key-only.sh` | 旧版入口，转发到 `ssh` 模块 |

## 模块约定

1. **风险分级**：低风险、可重复、容易验证的配置（时区、校时、补装工具）自动执行；改变登录方式、网络策略或整机软件的操作（SSH、防火墙、系统更新）必须先列出方案，再显式确认。
2. **可能断开连接的操作，完成后必须请用户另开窗口验证**；验证失败立即撤销本次修改。
3. **只改自己的东西**：写入前确认目标文件不存在或由本工具生成；修改记录保存在 `/var/lib/vps-init/<模块>/`，撤销只还原记录里的内容。已有的公钥、防火墙规则一律不删。
4. **先校验再生效**：写临时文件后原子替换；生效前做语法和最终值校验，失败时恢复原状。
5. **不猜测**：拿不到关键信息（例如 SSH 端口）时停止并说明原因，不用默认值代替。
6. **输出**：界面只显示步骤和结果；外部命令的完整输出通过 `run_task` 写入 `/var/log/vps-init.log`，失败时在界面展示日志末尾。
7. **交互**：一律通过 `/dev/tty` 读写，保证 `curl … | bash` 也能提问；没有终端时明确报错，不卡住、不默认同意。
8. **兼容**：状态文件格式变更时，新版本必须能读取并撤销旧版本留下的记录。
9. 菜单只放面向目标的入口，不把同一目标拆成多个选项；细分参数通过子命令提供。

## 测试

- 每个修改系统的分支（应用、撤销、回滚、拒绝）都应有行为测试，而不只是检查帮助文字。
- `tests/ssh.sh` 在 CI 中于 Debian 11/12、Ubuntu 20.04/22.04/24.04、AlmaLinux 9 容器内运行，覆盖 OpenSSH 8.2 到 9.9；在 GitHub 的 Ubuntu 主机上再以真实 systemd 运行一次（目前为 OpenSSH 10.2）。
- 防火墙测试使用 `tests/stubs/ufw` 和 `tests/stubs/ss` 替身，不触碰真实网络。

## 发布

改动先提交到独立分支，CI 全部通过后以 Pull Request 合并到 `main`。版本号在 `lib/common.sh` 中维护，变更记录写入 `CHANGELOG.md`。
