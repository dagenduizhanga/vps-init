# vps-init 架构与安全约定

## 目标

采用 Bash 实现轻量、模块化的 VPS 初始化工具。交互界面、命令行入口和独立模块共用同一套公共函数；模块可独立执行，不引入额外运行时依赖。

## 目录

- `install.sh`：远程下载启动器，不负责执行具体系统变更。
- `vps-init.sh`：统一命令入口、交互菜单和状态展示。
- `lib/`：公共日志、确认、系统检测、备份与恢复能力。
- `modules/`：SSH、系统初始化、安全加固等独立功能。
- `tests/`：Shell 脚本静态检查与行为测试。
- `docs/`：架构、安全和使用说明。

## 模块约定

1. 每个模块独立运行，明确声明需要的权限和支持的发行版。
2. 低风险、可重复且容易验证的基础配置应自动执行；涉及系统升级、防火墙启用、SSH 登录策略等高风险操作必须显式确认。
3. 修改配置前备份原文件，优先使用同目录临时文件加原子替换。
4. 修改后执行对应配置校验；校验失败时恢复备份并再次校验。
5. 不擅自删除用户数据、公钥或已有规则。
6. 防火墙模块不得默认启用防火墙或切换 SSH 端口，必须先确认当前 SSH 放行规则。
7. 模块未实现时明确提示，不得伪装成功或执行部分变更。
8. 系统初始化默认设置 `Asia/Shanghai`、启用 NTP 自动同步并补齐缺失的常用工具；重复运行应自动跳过已完成项目。
9. 不把同一目标拆成多个菜单选项；优先提供一键基础流程，保留必要的高级命令参数。

## SSH 迁移策略

SSH 实现位于 `modules/ssh.sh`。仓库根目录的 `ssh-key-only.sh` 仅作为兼容入口，将参数原样转发到模块，保持旧命令和自动化调用方式不变。

## 版本与发布

所有重构先提交到独立分支。通过 ShellCheck、Bats 和发行版测试后，再以 Pull Request 合并到 `main`。
